📋 Overview

VPOS is a business-focused Point of Sale management system developed by Value Tech Solutions for supermarkets and retail stores in India. Shopkeepers (retail store and supermarket owners) can self-register to access the platform. Other user roles (Admin, Service Agent, Manager) are created by authorized personnel only.

This Privacy Policy describes what information VPOS collects, how it is used, stored, and protected. By using any VPOS application (Admin, Billing, or Billing Offline), you agree to the practices described in this policy.

🗂️ Information We Collect

1. Shopkeeper Account Information

During Self-Registration (by Shopkeeper):

  • Mobile phone number (via OTP verification)

During Profile Completion or Account Creation by Admin/Service Agent:

  • Full name (displayName)
  • Email address
  • Password (encrypted)
  • Alternative phone number (optional)
  • Personal address (address1, address2, landmark, town, district, state, pincode)
  • Business alias (optional)
  • GST number (optional — for tax compliance)
  • Profile photo (optional)
  • Customer type (retail/wholesale/distributor — set by admin)
  • Number of branches allowed (set by admin)

2. Branch Information (Created by Shopkeepers)

Shopkeepers create and manage their own branch locations after registration:

  • Branch name
  • Branch address (address1, address2, landmark, town, district, state, pincode)
  • Branch phone number (optional)
  • Branch GST number (optional)
  • UPI ID for payments (optional)
  • GST collection settings (whether branch collects GST, GST slabs)
  • Primary/secondary branch designation

3. Manager Accounts (Created by Shopkeepers)

Shopkeepers create manager accounts for their branches:

  • Manager name, email, password
  • Manager phone number, alternative phone number
  • Manager address (address1, address2, landmark, town, district, state, pincode)
  • Assigned branches (which branches the manager can access)

4. Staff Accounts (Created by Shopkeepers/Managers)

Shopkeepers and managers create staff members for billing operations:

  • Staff name, phone number
  • Employee ID
  • Passcode (for billing device login)
  • Role (Operator, etc.)
  • Assigned branch

5. Service Agent Accounts (Created by Admins)

Admins create service agent accounts for support purposes:

  • Service agent name, email, phone
  • Permissions and access levels

6. Inventory & Business Data (Managed by Shopkeepers/Managers)

  • Product categories created by shopkeeper
  • Product names, prices, GST slabs
  • Product images (optional — can be disabled per branch)
  • Sales transactions, bill records, payment details
  • Subscription plan details and device count (assigned by admin)
  • Reports and analytics data

7. Customer Billing Data (Optional & Consent-Based)

Collection of end-customer information during billing is entirely optional. Shopkeepers may collect customer name and phone number only with the explicit consent of the customer. Value Tech Solutions does not mandate collection of customer data and bears no liability for unauthorized collection.

8. Device & Technical Data

  • Device model, manufacturer, Android/iOS version
  • Unique device identifier (Firebase installation ID)
  • Push notification token (Firebase Cloud Messaging)
  • App version and platform information
  • App crash logs and error diagnostics
  • Device registration and assignment history (managed by admin)

9. Activity & Audit Logs

  • User login history and timestamps
  • Account creation, modification, and deletion activities
  • Device scan and QR code scanning logs
  • Inventory and category modifications
  • Report generation and export activities
  • Retention: 90 days for audit logs, 90 days for activity logs

☁️ Data Storage & Security

Cloud Infrastructure

All data is stored on Google Firebase (Cloud Firestore and Firebase Storage), hosted on Google's secure cloud infrastructure in the asia-south1 (Mumbai, India) region. This ensures data sovereignty and compliance with Indian data localization requirements.

Encryption

  • In Transit: All data transmitted between apps and servers is encrypted using TLS 1.3
  • At Rest: Data stored in Firestore and Firebase Storage is encrypted at rest using AES-256 encryption
  • QR Codes: Device QR codes use AES-256-CBC encryption for secure device registration

Access Control

  • Firebase Authentication with role-based custom security claims (Admin, Service Agent, Shopkeeper, Manager)
  • Each shopkeeper can only access their own data — strict data isolation enforced by Firestore security rules
  • Service agents have limited read access for support purposes only
  • Managers can only access data from their assigned branches
  • Aadhaar ID numbers, where optionally provided, are stored in a restricted Firestore collection accessible only to authorized administrators

Security Measures

  • Firebase App Check to prevent unauthorized API access
  • Firestore Security Rules to enforce role-based access control
  • Regular security audits and vulnerability assessments
  • Audit logs for tracking sensitive operations
  • Two-factor authentication (2FA) available for admin accounts
